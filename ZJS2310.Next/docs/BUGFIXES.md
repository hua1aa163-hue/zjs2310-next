# 已处理的旧版缺陷

| 旧版问题 | 影响 | 新版处理 |
| --- | --- | --- |
| `(ok / total) * 100` 使用整数除法 | 良率大多数时间显示 0% | 使用 `100d * ok / total`，并处理分母为 0 |
| 每次 `NetworkStream.Read` 直接当成完整结果 | TCP 拆包、粘包时解析错乱 | `ProtocolMessageFramer` 按 `,%` / 换行累计分帧 |
| `Read` 返回 0 后仍无限循环 | 服务断开后 CPU 空转、状态仍像在线 | 0 字节视为正常断线，结束接收循环并通知 UI |
| 后台线程、System.Timers.Timer 直接更新 UI | 随机跨线程异常与死锁 | 核心流程无 UI 依赖，界面统一通过 `BeginInvoke` 回送 |
| 在 UI 线程大量 `Thread.Sleep` | 界面卡死、无法及时停止 | 全部改为可取消的异步延时 |
| 投影脉冲延时中停止可能来不及发送关闭帧 | 光机可能停留在错误输出状态 | 关闭帧放入 `finally`，即使取消流程也会发送 |
| `IsReceiveMsg` 与 1 秒轮询定时器驱动流程 | 竞态、重复发指令、状态难以恢复 | 串行异步状态机：准备画面 → 发指令 → 等对应结果 → 判定 |
| INI 阈值依赖写入顺序和数组下标 | 配方编辑后可能错绑指标 | JSON 以稳定指标键保存；旧 INI 也按键名导入 |
| `First()`、`Last()` 和结果数组直接取下标 | 缺项或短结果导致崩溃 | 所有协议下标先校验，错误作为明确步骤结果呈现 |
| 数字解析依赖系统区域设置 | 中文系统/小数点格式变化时解析不一致 | 仪器协议固定使用 `InvariantCulture` |
| 非数字 token 被静默写成 0 | 脏数据可能被误判为有效测量 | 严格解析，遇到非数字立即报告协议错误 |
| t1/t2 之外没有一致的超时保护 | 某一步无响应时流程永久等待 | 每个测试指令都有统一可配置超时 |
| 固定使用 `D:\pic`、`D:\测试软件...`、`C:\Users\111.jpg` | 换电脑即失败 | 图片、数据、日志和设备参数全部配置化 |
| 文件流与图片对象生命周期混乱 | 文件锁定和 GDI 资源泄漏 | 复制位图后立即释放源对象，切图时释放上一张图 |
| 登录连续使用多个独立 `if`，失败无提示 | 重名账号可能重复弹窗，错误体验不完整 | 单一认证服务，PBKDF2-SHA256 加盐保存密码 |
| 用户配置修改后没有明确持久化边界 | 设置可能未保存或散落在用户配置文件 | JSON 存储使用临时文件原子替换 |
| 超大主窗体混合协议、设备、Excel、业务和 UI | 修改任一功能都可能破坏其他模块 | 分为 Core、Infrastructure、UI 三层并通过接口解耦 |

旧项目本身在当前机器上能够编译，只有两个编译警告；本次修复重点是上述运行时和设计缺陷。
